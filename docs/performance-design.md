# Lychee Talent 性能规范与验收

状态：首版门禁与拟定预算；2026-09-27 已完成职业数据、真实客户端计数与图标选择器测量，见 [验证记录](../PERFORMANCE.md)。最终实现的图标关闭动作在本轮两次测量中为 0.20–0.27 ms，目录引用可回收；正常 GC 前刷新计数不会立即下降，重新打开约 44 ms。中间实现调用原生 `Release()` 曾产生 113–134 ms 的同步停顿，已替换。冷登录、战斗帧时间、自然 GC 发生时间、跨职业和长时间重复操作仍待验收，不能宣称全部 CPU 预算达标。继承相邻 Lychee 的事件驱动、按需创建、有界缓存、同值不写、完整成本归因原则；其历史数据不能作为本插件已达标证据。

## 1. 优先级

正确性与原方案保护 → 战斗帧时间稳定 → 日常交互响应 → 内存和分配可解释 → 动画装饰。不能用禁用主要功能、强制 GC、拆包漏算或静默截断数据获得漂亮数字。

## 2. 硬门禁

- 关闭且没有应用事务时，无插件 OnUpdate、ticker、循环 timer、搜索、排序或动画；只保留记录在案的最小事件处理。
- 战斗不执行配置切换、导入、动作条写入、数据预处理或整库扫描；不排队在脱战后偷偷提交。
- 不监听战斗日志、单位血量或光环等与天赋管理无关的高频事件。
- 一次只有一个应用事务。原生操作发出后必要的确认监听必须有截止时间，结束立即注销；不得无限轮询。
- 可见行复用，第一次达到池容量后反复滚动、开关不再累计创建 Frame、纹理、FontString 或动画组。
- 缓存、操作队列、恢复记录与诊断缓冲全部有界；关闭后旧对象不能通过回调继续持有业务数据。
- 不使用运行时 HTTP、全职业目录登录扫描、逐帧差异计算或定时全量 GC。
- 不宣称隐藏 Frame 即回收它；分别统计保留原生对象和可释放 Lua 引用。

## 3. 生命周期与触发成本

| 工作 | 触发 | 停止／失效 | 成本范围 |
| --- | --- | --- | --- |
| 最小启动 | 插件加载／角色就绪 | 初始化完成后移除一次性事件 | 不创建主 UI、不解析所有方案 |
| 职业数据加载 | 首次浏览该职业 | 留作有界只读数据，不假装可卸载 | 单职业／单发布版 |
| 列表筛选 | 场景、来源、搜索改变 | 新查询取代旧代次，关闭取消 | 当前专精及场景候选 |
| 天赋解析／校验 | 导出、保存副本或应用 | 内容／树版本变化失效 | 当前与目标两套天赋 |
| 应用事务 | 用户点击应用 | 成功、失败、中断、截止 | 单个目标与实际原生操作 |
| 动画 | 打开、关闭、选择、换页 | 终态、隐藏、取消、重绑 | 一个根节点或最多两条行 |
| 场景提示 | 区域变化 | 相同场景不重复处理 | ID 匹配，不扫描全部内容 |

实现前提交事件白名单与每项所有者。无窗口时专精／区域事件只标记轻量状态，界面打开再消费；不借事件偷偷做预热。

## 4. 拟定 CPU 预算

以下是设计目标，不是已测结果。以用户机器的固定客户端版本、同数据量与相同插件集测量；超限必须先归因和优化，不允许直接改目标掩盖卡顿。

| 场景 | 初始目标 | 口径 |
| --- | --- | --- |
| 无事务的隐藏空闲 | 0 周期性 Lua 工作 | 连续观察 60 秒，单独报告必要事件 |
| 最小启动 | 自身同步工作 ≤2 ms | 不包含游戏／其他插件加载时间，另报整体影响 |
| 首次打开 | 最大 Lua 批次 ≤2 ms；内容可用目标 ≤100 ms | 分别报告首次资源加载和完整内容时间，不用空框伪装完成 |
| 热打开、单次选择 | p95 ≤1 ms，最大 ≤2 ms | 至少 100 次；不计人为动画时长 |
| 搜索／场景过滤 | 单批 ≤1 ms，结果目标 ≤50 ms | 100／1000／容量边界方案分别测，最大值单报 |
| 动画活动帧 | Lua 自身目标 ≤0.15 ms／帧 | 整体帧时间另测；原生动画成本也不能省略 |
| 关闭清理 | 自身同步工作 ≤1 ms | 超限按引用与对象数量归因 |

应用天赋涉及游戏 API 与服务器确认，不承诺固定完成毫秒数；分别报告插件自身耗时、原生调用、等待及最坏单帧成本。首版拟定 10 秒单阶段确认截止、30 秒总截止，实测后调整；截止是停止盲等并进入恢复状态，不是断言游戏已回滚。

## 5. 数据与缓存预算

| 数据 | 初始容量政策 | 所有者与淘汰 |
| --- | --- | --- |
| 方案行池 | 可见 K + 2，常规视口预期不超过 12 | UI 持有固定池；重绑清事件、hover、按下身份 |
| 已解析天赋 | 16 条；单条导入串上限 16 KiB | 解析模块；按内容哈希＋树版本，LRU，活动引用受保护 |
| 用户方案 | 账号 1000 条，记录逻辑总量 16 MiB | Storage；到限拒绝新写并提供导出，不删除旧记录 |
| 最近记录／恢复记录 | 最近 20 条、活动恢复 1 条 | Storage；不无限积累完整配置快照 |
| 诊断缓冲 | 100 条简短记录 | 环形覆盖，不保存密钥或完整 WCL 报告 |
| 内置数据 | 每场景默认最多 3 个不同组合 | 构建去重；按职业分片，不静默砍场景 |

容量是首版输入边界，实施前用真实字符串与目录验证是否足够；变更需记录理由。逻辑字节上限不等于 Lua 实际内存。用户方案被删除时清理相关缓存和绑定引用，原生方案清理必须显式处理，不能随用户记录删除而静默删除游戏配置。

保留内存不设置无证据的绝对 KiB 成功线。每次报告全部加载包、SavedVariables、索引、解析缓存、Frame/纹理/动画组数量及纹理尺寸；有限且有用途的增长可以审查接受，重复操作持续增长直接失败。

## 6. UI 与算法约束

- 搜索先按专精、场景和来源收窄，再做简单名称匹配；不提前建立多套重复中文索引。
- 滚动只重绑可见行；筛选与排序仍需按真实候选量计费，不能因行池是 K 就声称整个查询 O(K)。
- setter 缓存只在调用成功后更新；同文本不 SetText，同位置不 SetPoint；字体、缩放与语言改变必须正确使缓存失效。
- 按下到松开核对记录身份、内容版本与绑定代次，防止滚动复用触发错方案。
- 大工作分批并可取消；只有未完成批次时才安排下一批。隐藏、战斗或新查询取消旧任务。
- 动画只在活动期间持有驱动；减少动态效果为即时终态；重开不能被旧关闭回调隐藏。
- 安全与配置校验不得为了性能跳过；优先简化对象和重复工作。

## 7. 验收矩阵

1. 冷登录、首次开窗、热开窗 100 次；记录加载、首内容、可交互、整帧峰值。
2. 滚动／筛选／详情切换 200 次；统计对象高水位、累计分配与关闭后保留走势。
3. 100、1000 条用户方案及内置职业分片；包含长中英文、空结果和命中全集。
4. 战斗前／战斗中／应用期间进战斗；未发出写入的操作取消，已发出操作只做有界核对。
5. 独立／共享动作条、切回原方案、配置容量满、绑定外部删除、未提交改点、专精改变、重载恢复。
6. 按下→重绑→松开、快速开关反向、减少动态效果、首次打开与 UI 缩放。
7. WCL 离线数据过期、错误字符串、错误专精、未知树版本；全部拒绝不兼容应用。

报告必须记录客户端版本、机器、插件集、数据量、样本数、p50/p95/最大值与前后对照。诊断工具自身开销单独说明。离线纯逻辑测试只能证明数据与状态机，不替代原生 API、动作条、taint 和游戏帧时间验证。

## 8. 发布条件

核心切换正确性、原方案／动作条保护、无隐藏循环工作、对象池稳定与国际化全部通过，才能宣称首版可用。性能未实测时只能说“按性能优先设计”，不能说“极低开销已保证”。

字号／行高放大后继续使用同一行池；可见容量按 46 的步长计算。删去三个菜单项及收藏排序，不新增布局监听。应用新增事件仅在现有事务内订阅；Ready 路径最多显式提交一次，等待确认期间不循环重试。失败原因只保存在现有单条恢复记录中。
