# 天赋应用与动作条

双击应用方案；省略号菜单中的“独立动作条”默认不勾选，只保存偏好，下次应用时生效。共用与独立的产品规则见 [产品定义](../product.md#应用与动作条)。每个角色、每个专精只绑定一个原生方案，中文名“荔枝天赋”，英文名“Lychee Talent”。推荐方案和自建方案均更新这一个原生配置。

## 唯一应用流程

1. 检查战斗、专精、字符串、鼠标光标和未提交改点。手动改点需要明确确认，不能覆盖已变化的确认对象。
2. 读取当前动作条，并保存到离开前的共用或独立布局。共用布局首次启用时记录，之后不被独立布局覆盖。读取并固定目标布局；读取失败在天赋提交前返回。宏只读复用，不检查空位。
3. 按保存的精确 ID 和名称验证原生工作方案。没有绑定时创建一次；重命名和动作条模式设置等待原生事件确认。
4. 原位重置和购买目标天赋，提交到同一个原生配置。天赋已经一致时直接恢复动作条，不重新读条。
5. 原生确认实际天赋与保存天赋后，把保存的宏引用解析到当前原生编号，再比较 180 槽并写入差异。已有技能从本次快照查找，恢复后统一核对并保存。写槽失败保留快照并尝试回滚已改槽位。失效宏引用保留原槽位和备份，其余动作继续恢复。
6. 天赋验证通过即记录已切目标，并显示“已应用”；后续动作条失败只记录内部局部结果和保留目标，暂停自动保存与自动重试。显式再次应用同一目标只重试尚未完成的动作条；最近八条失败摘要不被成功重试覆盖。结束时释放操作事件与计时器。一次操作有 25 秒上限，不轮询，不重复发送未确认的提交。

原生配置更新可能在活动树与保存配置同步完成前连续到达。普通通知合并到下一帧核对一次，内容不一致时等待后续通知，不重复提交或主动轮询；提交失败、战斗和专精变化立即停止操作。购买前的位置排序只读取一次节点坐标，购买和最终天赋核对仍使用实时数据。

## 状态边界

- `actionBars.specs[spec].working`：唯一原生配置的精确身份。
- `default`：该专精的默认动作条，独立方案切换不会覆盖它。
- `profiles[buildID]`：各方案的独立动作条，保存退出前的手动调整。
- `modes[buildID]`：本专精内明确选择的动作条模式，缺省为共用。
- `applied`：本专精最近已验证的天赋结果；`partial`／`barsPending` 区分动作条待处理。实际写槽失败后由 `pendingBars` 保留完整目标并暂停编辑保存；局部缺宏在快照 `pendingMacros` 中保留。
- 角色级 `nativeMacros`：登记原生宏的逻辑引用及最近确认内容；仅记录当前原生引用；插件不改写或删除游戏中的宏。
- 角色级 `recovery`：最近一次操作的原始天赋和动作条，用于诊断与恢复。

不接管旧版编号原生方案或方案×模式原生绑定。自建原生方案不能按名称前缀收养或删除。旧版插件数据不再使用；客户端加载本版本时，账号与角色根各自按 V2 schema 重建，已是 V2 的另一根保留，规则见 [架构说明](../architecture.md#数据归属)。业务读取路径只处理新格式。

快照不包含键位、第三方动作条位置或界面布局。版本 2 将宏原文、名称、选定图标与槽位引用分开保存；`nativeID` 是布局引用；当前原生编号仅保存在角色级观察登记中，不作为旧记录的恢复依据。`Macros:Pack / Physical / Refresh` 只读取和解析原生宏引用；同一原生宏的正文在全部布局间共享，备份不回写。`ActionBars:Restore` 负责动作槽的恢复、验证与回滚；`pendingMacros` 保留局部待恢复引用。随机偏好坐骑使用原生特殊动作编号；普通坐骑统一为 mountID。

当前未学会且无法拾取的技能按 [架构中的待恢复技能规则](../architecture.md#应用事务与动作条) 保存，不中断其余动作恢复。实际槽位与待恢复记录分开，退出、重载和被动保存不会丢失记录；手动改变该槽位会取消对应待恢复技能。

`UPDATE_MACROS` 只读比较宏表并更新当前布局，槽位通知合并为只读观察。被动读取不能消除同名宏歧义时保留上次记录，下一次完整捕获再读取准确引用；完整捕获仍不可读的槽位保留并提示。宏正文的全局编辑不改变布局的槽位保存归属。登录或切回专精时，在原生工作配置与天赋匹配后恢复该专精保存的内容，失败不自动反复重试。完整机制见 [架构说明](../architecture.md#应用事务与动作条)。
