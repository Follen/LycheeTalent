# 天赋应用与动作条

双击应用方案；省略号菜单中的“独立动作条”只保存偏好，下次应用时生效。每个角色、每个专精只绑定一个原生方案，中文名“荔枝天赋”，英文名“Lychee Talent”。推荐方案和自建方案均更新这一个原生配置。

## 唯一应用流程

1. 检查战斗、专精、字符串、鼠标光标和未提交改点。手动改点需要明确确认，不能覆盖已变化的确认对象。
2. 保存离开前的独立动作条。默认布局首次启用时记录，之后不被独立布局覆盖。
3. 按保存的精确 ID 和名称验证原生工作方案。没有绑定时创建一次；重命名和动作条模式设置等待原生事件确认。
4. 原位重置和购买目标天赋，提交到同一个原生配置。天赋已经一致时直接恢复动作条，不重新读条。
5. 原生确认实际天赋与保存天赋后，预检并恢复对应的 180 个动作条槽位。失败保留快照，并尝试回滚已改槽位。
6. 成功才更新当前标记；结束时释放操作事件与计时器。一次操作有 25 秒上限，不轮询，不重复发送未确认的提交。

## 状态边界

- `actionBars.specs[spec].working`：唯一原生配置的精确身份。
- `default`：该专精的默认动作条，独立方案切换不会覆盖它。
- `profiles[buildID]`：各方案的独立动作条，保存退出前的手动调整。
- `applied`：最近已验证的应用结果。
- `recovery`：最近一次操作的原始天赋和动作条，用于诊断与恢复。

不包含旧版编号方案、方案×模式原生绑定、旧版恢复记录推断或运行时迁移。当前角色的一次性整理通过独立、有记录的维护探针完成，不随插件发布。自建原生方案不能按名称前缀收养或删除。

快照不包含键位、第三方动作条位置或界面布局。宏按名称、正文与账号／角色范围识别；同名不同内容的歧义宏拒绝恢复。坐骑统一为 mountID，避免原生接口在 companion 与 summonmount 之间转换造成误判。无法恢复的动作保留原快照并明确报错。
