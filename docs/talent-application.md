# 天赋应用与动作条

双击应用方案；省略号菜单中的“独立动作条”默认不勾选，只保存偏好，下次应用时生效。共用与独立的产品规则见 [产品定义](../product.md#应用与动作条)。每个角色、每个专精只绑定一个原生方案，中文名“荔枝天赋”，英文名“Lychee Talent”。推荐方案和自建方案均更新这一个原生配置。

## 唯一应用流程

1. 检查战斗、专精、字符串、鼠标光标和未提交改点。手动改点需要明确确认，不能覆盖已变化的确认对象。
2. 读取当前动作条，并保存到离开前的共用或独立布局。共用布局首次启用时记录，之后不被独立布局覆盖。预检目标宏需要的角色宏空位，空位不足在天赋提交前返回。
3. 按保存的精确 ID 和名称验证原生工作方案。没有绑定时创建一次；重命名和动作条模式设置等待原生事件确认。
4. 原位重置和购买目标天赋，提交到同一个原生配置。天赋已经一致时直接恢复动作条，不重新读条。
5. 原生确认实际天赋与保存天赋后，把保存的宏内容解析到原生宏，再比较 180 槽并写入差异。已有技能从本次快照查找，恢复后统一核对并保存。失败保留快照，并尝试回滚已改槽位、已改宏正文及新建宏。
6. 成功才更新当前标记；结束时释放操作事件与计时器。一次操作有 25 秒上限，不轮询，不重复发送未确认的提交。

## 状态边界

- `actionBars.specs[spec].working`：唯一原生配置的精确身份。
- `default`：该专精的默认动作条，独立方案切换不会覆盖它。
- `profiles[buildID]`：各方案的独立动作条，保存退出前的手动调整。
- `modes[buildID]`：本专精内明确选择的动作条模式，缺省为共用。
- `applied`：本专精最近已验证的应用结果，决定当前编辑的保存归属。
- 角色级 `macroPool`：登记插件可重复替换的角色宏；不作为布局内容的来源。
- 角色级 `recovery`：最近一次操作的原始天赋和动作条，用于诊断与恢复。

不接管旧版编号原生方案或方案×模式原生绑定。自建原生方案不能按名称前缀收养或删除。旧版插件布局、模式与应用状态的字段迁移见 [架构说明](../architecture.md#数据归属)；只转换仍可读取的旧宏，不补造已经丢失的原文。

快照不包含键位、第三方动作条位置或界面布局。版本 2 将宏原文、名称、选定图标与槽位引用分开保存；原生编号只是编辑关联的绑定信息。`Macros:Plan / Execute / Rollback` 负责宏复用与写入，`ActionBars:Restore` 负责整套布局的恢复、验证与回滚。随机偏好坐骑使用原生特殊动作编号；普通坐骑统一为 mountID。

`UPDATE_MACROS` 只读比较宏表并更新当前布局，槽位通知合并为只读观察。被动读取不能消除同名宏歧义时保留上次记录，下一次完整捕获再读取准确引用；完整捕获仍不可读的槽位保留并提示。插件自己的宏替换不反向保存到离开的布局。登录或切回专精时，在原生工作配置与天赋匹配后恢复该专精保存的内容，失败不自动反复重试。完整机制见 [架构说明](../architecture.md#应用事务与动作条)。
